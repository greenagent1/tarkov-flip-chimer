# tarkov-flip-chimer

PowerShell-инструмент для мониторинга цен на барахолке Escape from Tarkov.
Программа периодически опрашивает цены и воспроизводит звук **chime** в тот момент, когда отслеживаемый предмет достигает порога покупки или продажи — так можно флипповать сделки, не уставившись в экран.

## Возможности

- **Алерты на покупку** — звук при падении цены ниже цели (фиксированная сумма или % от среднего)
- **Алерты на продажу** — звук при росте цены выше цели
- **Живая таблица** — прокручиваемая консольная таблица с текущей ценой, целью, Diff%, средним за 24ч и временем последнего обновления
- **Дедупликация** — звук повторяется только при изменении цены, не каждый цикл опроса
- **Бесплатный режим** — работает без регистрации через [tarkov.dev](https://tarkov.dev)
- **Игровые режимы** — отслеживание цен PvP, PvE или PvP Season (`gameMode = pvp | pve | pvps`)

## Забанят ли меня?

Нет. Инструмент никак не взаимодействует с игровым процессом — он обращается к публичным API цен в фоновом терминале.

Для сравнения: [RatScanner](https://ratscanner.com) накладывает данные о предметах прямо поверх окна Таркова, парсит экран в реальном времени — и даже за него не банят. Этот инструмент значительно менее инвазивен: он просто читает сайт.

## Требования

- Windows 10 / 11
- PowerShell 5.1 и выше (входит в состав Windows)
- *(Опционально)* Платный API-ключ на [tarkov-market.ru/dev/api](https://tarkov-market.ru/dev/api) — для более быстрых и надёжных данных, а также среднего за 7 дней. Обязателен, если нужен `gameMode = pvps` до того, как tarkov.dev добавит данные по сезону

## Быстрый старт

1. **Создайте конфиг** — скопируйте `config.example.ini` в `config.ini`.

2. *(Опционально)* **Добавьте API-ключ** — оформите подписку на tarkov-market.ru, откройте раздел API и вставьте ключ в `config.ini`.
   Без ключа инструмент использует [tarkov.dev](https://tarkov.dev) бесплатно (может быть медленнее и менее надёжным).
   Смотрите скриншот [`how-to-get-api-key.png`](how-to-get-api-key.png):

   ![Как получить API-ключ](how-to-get-api-key.png)

3. **Добавьте предметы** — по одной секции `[Item.<Метка>]` на предмет.
   Найдите предмет на [tarkov-market.ru](https://tarkov-market.ru) и используйте его название как значение `query` (смотрите [`where-to-get-item-name.png`](where-to-get-item-name.png)):

   ![Как найти название предмета](where-to-get-item-name.png)

   ```ini
   [Item.PACA]
   query = PACA Soft Armor
   alert = 29000          ; купить когда цена < 29 000 ₽

   [Item.Bitcoin]
   query     = physical bitcoin
   avgSource = avg24h
   alert     = S7%        ; продать когда цена > 7% выше среднего за 24ч
   ```

4. **Запустите** — дважды кликните `run.bat` (или выполните `.\Check-TarkovPrices.ps1` в терминале).

| `tarkovDevMode` | (авто) | Продвинутая/опциональная настройка: переопределяет, какой путь `json.tarkov.dev/<режим>/` используется для бесплатного источника, если автоматическое сопоставление с `gameMode` когда-нибудь ошибётся |
| `soundFile` | `alert.wav` | Путь к звуку (относительно папки со скриптом) |
| `volume` | `5` | Громкость 0–100 |
| `windowHeightOffset` | `0` | Подстройка автоматически вычисленной высоты окна консоли в строках. Отрицательное значение уменьшает (напр. `-7`), положительное увеличивает (напр. `+3`). |
| `debug` | `no` | `yes` — зеркалить каждый отрисованный кадр (таблица + алерты, без цвета) в `debugFile`. Помогает диагностировать некорректные данные или поехавшую табуляцию без скриншотов консоли |
| `debugFile` | `analytics/debug-console.txt` | Путь к файлу debug-зеркала (относительно папки со скриптом) |

### `[Item.<Метка>]`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `query` | — | Строка поиска для API (**обязателен**) |
| `alert` | — | Порог срабатывания (**обязателен**) — формат ниже |
| `label` | имя секции | Подпись в таблице. Полезно, чтобы две секции отображались с одинаковой меткой (например, одна на покупку + одна на продажу того же предмета) |
| `avgSource` | `avg7d` | Опорное среднее: `avg7d`, `avg24h`, дробный вес (`0.7`, `1.3` и т.п.) — смесь между двумя средними, или целое число — фиксированная цена. См. [Взвешенный `avgSource`](#взвешенный-avgsource) |
| `used` | `no` | `yes` = отслеживать самый дешёвый (изношенный) вариант; `no` = самый дорогой (новый) |

**Формат alert**

| Пример | Смысл |
|---|---|
| `15000` | Купить при цене < 15 000 ₽ |
| `B15000` | То же самое (явный признак покупки) |
| `S45000` | Продать при цене > 45 000 ₽ |
| `B15%` | Купить при падении цены более чем на 15% ниже `avgSource` |
| `S7%` | Продать при росте цены более чем на 7% выше `avgSource` |

#### Один предмет, два направления

Заголовки секций должны быть уникальны, но две секции могут иметь одинаковую отображаемую подпись через `label` — удобно, когда нужны и алерт на покупку, и алерт на продажу одного и того же предмета без стрелочек в названиях:

```ini
[Item.BitcoinBuy]
query     = physical bitcoin
label     = Bitcoin
avgSource = avg24h
alert     = B5%

[Item.BitcoinSell]
query     = physical bitcoin
label     = Bitcoin
avgSource = avg24h
alert     = S7%
```

Обе строки в таблице показываются как `Bitcoin` — но триггеры покупки и продажи независимы (своё состояние, своя дедупликация), а подпись одна.

#### Взвешенный `avgSource`

`avgSource` принимает десятичный **вес**, который смешивает два средних с API:

```
refAvg = avg7d + w * (avg24h - avg7d)
       = avg7d * (1 − w) + avg24h * w
```

Десятичная точка в значении — признак "это вес": `1.0` — вес, `1` — фиксированная цена.

| `avgSource` | Что значит |
|---|---|
| `0.0` | чистый `avg7d` (самое стабильное, медленно реагирует) |
| `0.5` | ровно посередине |
| `1.0` | чистый `avg24h` (быстро, но шумно) |
| `0.7` | в основном 24ч, слегка приякорено к 7д |
| `1.3` | экстраполяция **за** `avg24h` — усиливает свежий тренд (разрыв между 7д и 24ч) |
| `2.0` | удвоенная амплитуда тренда — агрессивно |

**Зачем это нужно.** Текущая цена шумит вокруг своего среднего. Когда `avg24h ≈ avg7d` — рынок спокоен, `refAvg` почти не двигается, какой бы `w` ни выбрал — поэтому мелкие колебания не пробивают триггер. Когда `avg24h` уходит от `avg7d` — это реальный сдвиг, и при `w > 1` `refAvg` уходит туда сильнее, ускоряя срабатывание алерта.

**Цифры на пальцах** (при `avg7d = 100 000 ₽`):

| Рынок | `avg24h` | `w=0.0` | `w=0.5` | `w=0.7` | `w=1.0` | `w=1.3` | `w=2.0` |
|---|---:|---:|---:|---:|---:|---:|---:|
| Штиль | 100 500 | 100 000 | 100 250 | 100 350 | 100 500 | 100 650 | 101 000 |
| Тренд вверх +5% | 105 000 | 100 000 | 102 500 | 103 500 | 105 000 | 106 500 | 110 000 |
| Тренд вниз −3% | 97 000 | 100 000 |  98 500 |  97 900 |  97 000 |  96 100 |  94 000 |

При штиле выбор `w` почти ни на что не влияет (строка остаётся около 100k). При тренде `w` решает, насколько агрессивно `refAvg` следует за движением.

**Бесплатный режим.** `avg7d` через бесплатное API недоступен, поэтому при отсутствии ключа дробный вес автоматически сводится к `avg24h`.

**Примеры:**

```ini
; Стабильная опора — купить, если цена ушла на 15% ниже 7-дневного среднего,
; кратковременные просадки игнорируются.
[Item.WaterFilter]
query     = water filter
avgSource = avg7d         ; то же самое, что 0.0
alert     = B15%

; Сглаженная середина — реагируем на свежие сдвиги, но не гоняемся за шумом 24ч.
[Item.LedX]
query     = LEDX
avgSource = 0.5
alert     = B10%

; В основном 24ч, слегка приякорено к 7д — быстро, но устойчиво к одиночным выбросам.
[Item.GpuBuy]
query     = Graphics card
label     = GPU
avgSource = 0.7
alert     = B12%

; Усиленный тренд — refAvg уходит за 24ч в направлении 7д→24ч.
; Удобно для триггеров на продажу при растущем рынке.
[Item.GpuSell]
query     = Graphics card
label     = GPU
avgSource = 1.3
alert     = S10%
```

### `[Separator.<Метка>]`

Вставляет горизонтальный разделитель с подписью между строками айтемов. Позиция в файле определяет место в таблице. Текст берётся из названия секции.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `color` | `DarkGray` | Цвет линии — название PowerShell ConsoleColor или hex `#RRGGBB` |

**Названия цветов** (PowerShell ConsoleColor):

| Цвет | | Цвет | |
|---|---|---|---|
| `Black` | | `DarkBlue` | |
| `DarkGreen` | приглушённый зелёный | `DarkCyan` | приглушённый голубой |
| `DarkRed` | приглушённый красный | `DarkMagenta` | фиолетовый |
| `DarkYellow` | коричнево-оливковый | `DarkGray` | тёмно-серый *(по умолчанию)* |
| `Gray` | нейтральный | `Blue` | синий |
| `Green` | покупка / позитив | `Cyan` | информационный |
| `Red` | продажа / негатив | `Magenta` | ярко-фиолетовый |
| `Yellow` | алерт | `White` | яркий |

**Hex-цвета** — любой RGB через `#RRGGBB`, например `#8B4513` (коричневый), `#6A0DAD` (фиолетовый), `#4B8BBE` (синий Питона).

```ini
[Separator.Броня и снаряжение]
color = DarkCyan

[Separator.Ценности]
color = #8B6914
```

### `[Column.Break]`

Опционально. Если присутствует, вывод делится на две колонки бок о бок, разделённые вертикальной чертой (`│`) — секции выше попадают в левую колонку, ниже — в правую. Удобно при длинном списке айтемов: окно становится ~в 2 раза шире и ~в 2 раза ниже. Без `[Column.Break]` используется обычная одноколоночная вёрстка.

У блока алертов внизу три варианта раскладки, проверяются в этом порядке:

| Ключ | По умолчанию | Описание |
|---|---|---|
| `alertWrapAfter` | выкл | Как только число алертов превышает это значение, они продолжаются во второй колонке вместо роста вниз. Делит по чистому счётчику, а не по buy/sell — поэтому перекос (например 20 алертов на покупку и 1 на продажу) всё равно заполняет обе колонки, а не скроллит таблицу за пределы окна. Имеет приоритет над `splitTriggers`, если заданы оба. |
| `splitTriggers` | `no` | Если `yes` (и `alertWrapAfter` не сработал), триггеры из левой колонки идут вниз слева, из правой — вниз справа. Удобно, когда слева список на покупку, а справа на продажу — но при перекосе одна сторона всё равно растёт бесконтрольно, т.к. делится по стороне, а не по количеству. |

Если не задано ни то ни другое, алерты выводятся одним вертикальным списком.

```ini
[Item.PACA]
query = PACA Soft Armor
alert = 29000

[Column.Break]
alertWrapAfter = 10   ; переносить алерты во 2-ю колонку после 10, независимо от стороны
splitTriggers  = yes  ; резервный вариант, пока алертов меньше alertWrapAfter

[Item.Hawk]
query = Gunpowder "Hawk"
alert = S25000
```

### `[Logging]`

Опционально. Если включено, в файл лога дописывается одна строка JSON Lines на цикл. Новая строка пишется только тогда, когда у хотя бы одного предмета текущая цена изменилась относительно предыдущего цикла (первый цикл записывается всегда — чтобы зафиксировать стартовое состояние). Содержимое строки — те же поля, что выводятся на экран.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `enabled` | `no` | `yes` — включить JSON-лог |
| `path` | `prices.log.jsonl` | Путь к файлу лога (относительно папки скрипта) |
| `maxEntries` | — | На старте оставить не больше N последних строк (пусто = без лимита) |
| `maxSizeKB` | — | На старте обрезать старые строки так, чтобы файл влезал в N КБ (пусто = без лимита). Можно задать оба — применяется более жёсткий |

```ini
[Logging]
enabled    = yes
maxEntries = 5000
maxSizeKB  = 1024
```
